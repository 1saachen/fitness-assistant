# 健身助手工作日志与路线图

> 这是一份持续维护的项目状态文件。每完成一个可验证阶段，就在“更新记录”中追加一条记录，并同步勾选路线图中的任务。

## 最终目标

构建一个面向个人健身管理的本地优先、多智能体可扩展助手。用户先填写自己的档案，系统据此生成包含训练、饮食、补剂优先级、睡眠和恢复的综合计划；用户每天提交训练、饮食、睡眠、疲劳和体重反馈，系统记录历史、识别独立问题、只调整受影响的部分，并说明每次调整使用了哪些知识来源。

当前验证档案是：22 岁，180 cm，80 kg，体脂约 20%，目标为减脂并保持力量；已训练 2 年，每周可训练 4 次，有健身房；主要吃学校食堂，偶尔外卖或速食；饮食预算约 40 元/天；无已知影响运动的问题，无已知食物过敏。

项目首先服务于这个单人本地场景，同时保留向多用户、外部模型和更多自动化能力扩展的接口。当前演示模式不调用外部模型 API，外部模型 API 调用数为 0。

## 决策记录

- 计划采用“全量适用 baseline 策略 + 反馈 issue-level 检索”，因为全面方案和针对性调整是两种不同的检索任务。
- 每个 issue 的 3-5 条限制只作用于该 issue；多 issue 反馈允许超过 5 条总引用。
- 使用结构化本地知识卡和审核发布，而不是让模型直接阅读未经审核的整段转写。
- 知识快照随计划/advice 保存，保证知识库以后变化不会改变历史解释。
- 知识不可用时继续提供规则核心流程，并明确记录状态。
- 容量超限采用整体降级，避免只保存部分来源造成不可审计结果。
- 先完成可测的关键词检索基线，再用离线评估决定是否引入向量检索。
- 当前保持 demo-only，避免在安全和成本边界未定义前接入外部模型。
