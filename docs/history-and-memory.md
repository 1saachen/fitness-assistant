# 历史、反馈与后续调整

原始反馈、结构化事实、个人记忆和计划版本分别保存。原文是用户报告；模型回应是解释；记忆是有来源的摘要；最终计划通过既有校验和确认流程生效。这些机制提供上下文适应，不会训练或微调模型。

## 同日补充与纠错

趋势以日期为样本单位。同一天可以有多条反馈，原记录均保留；统计时按字段合并，采用最后一次实际修改的非空值。`null`、空列表和缺失字段不清除已知事实；`false`、`0` 是有效值。修订中只改体重，不会刷新睡眠或训练字段的事实时间。

动作按场次和动作标识合并，再分别追踪组数据、重量、RPE及质量说明的最后修改时间。没有场次标识时，同日同动作默认归为同一场次；同日多练需要明确提供不同的 `session_id`。模型提取的场次标识必须出现在原文中；导入可以携带稳定标识。不同名称的动作不会自动认定为同一变式。

## 最近信息如何进入规划

| 上下文 | 默认范围与限制 |
| --- | --- |
| 训练及反馈复盘的近期原文 | 最近14个日历日，最多4条 |
| 营养规划的近期原文 | 最近14个日历日，最多21条 |
| 训练的同动作实际表现摘要 | 最近21个日历日，每个动作最多3场 |
| 按需训练历史工具 | 可选择7、14或21天、动作ID、每动作1至8场 |
| 个人记忆 | 按事件日期、有效期、来源修订和适用日期筛选 |

日期窗口包含截止日；优先分配到不同报告日期，再容纳同日补充，避免某天多次提交挤掉整个历史窗口。原文摘要和逐组摘要均有字节预算，截断会标明；完整原记录仍可检索。训练工具最多展示每场前12组，但合计基于全部已记录组。历史反馈复盘截止于该反馈日期和今天中较早者，未来记录不会提前参与解释，补充记录也不能引用日期更晚的父记录。

这些信息与当前档案、长期计划、恢复状态和确定性趋势一起进入模型上下文。模型可据此建议保持负荷、先稳定次数或降低下一次负担，程序校验候选和适用范围。不存在仅凭一次 RPE 自动加减重量的通用规则；单次表现也不会自动重写档案1RM或已确认长期处方。

## 实际逐组表现

例如“卧推45kg，8/8/7次，末组RPE9”可保存三组实际记录，前两组RPE未知，第三组为9。每组支持实际次数、可选重量、可选RPE和完成状态；动作另支持质量说明、动作目标完成状态和场次标识。旧的动作重量/RPE字段继续可读。

实际23次、已知外部负重训练量1035kg由程序计算。若部分组重量未知，仅提供已知部分并标记训练量不完整；未完成组仍计入其已实际做出的次数。训练量不是1RM、动作质量或进步结论。记录某个动作不代表整次训练完成，计划或未来意图也不会当作已发生事实。

JSON、Markdown结构块和CSV导入导出保留逐组数据；CSV的 `exercise_results` 列使用JSON，饮食条件字段也参与往返。缺失的旧记录字段仍保持未知，不反推过去的组数或次数。

## 记忆的来源与生命周期

新记忆包含事件日期、反馈ID、修订号和原文摘录；每个引用都要能在对应原文中找到。普通临时事实默认有效14天，模型归纳默认21天，截止日均包含在内。过期条目停止参与当前规划，原文和旧记忆版本继续保留。多日模式至少需要两个不同日期的来源，并标为待验证；引用存在不等于归纳已被证明。

“今天想吃米饭”只影响短期安排；明确长期喜欢、不喜欢或以后持续采用的表达才可成为长期偏好候选。个人记忆页可确认偏好或选择“不再采用”，操作会留下明确用户声明、来源和新记忆版本，不自动修改档案。

明确更正可通过 `supersedes` 替代已有记忆；不能自行引用新建键、制造替代环或无依据解除限制。普通条目的来源修订变化后暂停使用，等待重新理解。过敏及未解除限制继续保留并标明来源已更正，防止补填体重时意外消失；限制需要针对性的明确解除表达，不能用普通偏好停用入口解除。

旧记忆无摘录时标为待核实；旧临时事实仍按来源日期到期。压缩保留偏好、限制、未解问题及其来源，不通过重写日期续期，不伪造用户确认。压缩失败保留旧记忆，不删除原始记录。

## 关键事实确认与失败处理

若训练或饮食完成状态不明确，反馈页给出明确选择。确认会新增反馈修订并保留原文；此前模型理解和计划调整输入失效，页面提示重新评估。确认本身不会重新生成当天计划。日终复盘默认保留当天，后续未来安排由模型决策；长期修改仍需确认新草稿。

某个辅助事实无法校验时，只舍弃该字段并显示提示，其他有效事实、已保存原文和有效回应仍可保留。原文校验检查所在完整语句，防止从“没有完成训练”截取“完成训练”，或将明天的打算当作今天已完成。

当前验证包含合成数据与模型桩，不代表真实模型每次都能正确理解自然语言。复杂或含混组次宁可保留未知；证据和结构校验不能完全验证解释、长期归纳或选重质量。用户可以补充、更正并重新理解。
