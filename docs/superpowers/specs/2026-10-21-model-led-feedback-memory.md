# 模型主导反馈与个人记忆

用户目标：自然语言反馈由模型理解、积累、检索和决策，不再把字段解析当作反馈流程主体。模型结合历史与专业知识决定维持、追问、建议或调整。

## 数据与决策流程

1. 原始反馈先保存为用户报告；提交成功不依赖模型成功。模型生成的理解与原始报告明确区分。
2. 输入当前原文、近期原文、当前计划摘要、版本化个人记忆。提供按需检索历史原文与专业知识的只读工具；个人记忆和专业知识分别标注来源。
3. 模型输出自然语言回应、建议、后续问题、记忆更新以及计划决策。数值事实为可选辅助提取，仍须有原文依据。不得把模型假设变成用户事实。
4. 原文、模型回应与计划决策可追溯。只有模型提出调整时才调用规划器；不再因每次提交反馈无条件重新生成。
5. 默认反馈是训练结束或睡前的日终复盘，不改写当天计划。模型可决定维持、给建议、追问或自动调整未来日计划；长期变更只生成新草稿，等待用户确认。仅当用户明确选择调整尚未完成的安排时，允许调整今天剩余部分，已完成内容仍保留。补录历史反馈不会回写历史计划。
6. 回答追问作为新反馈提交，可附上上一条反馈ID；新的模型输入含前次问题与回应，不要求用户重写档案。

## 个人记忆

版本化记忆条目包含key、类别、文字、原始反馈ID及修订号。允许事实、用户偏好、临时限制、待确认信息、模型归纳的模式；类别必须区分，模式不等于已证实因果。

模型可以更新条目或明确取代旧条目，系统保留历史版本。个人档案不自动被记忆更新覆盖；当前更正优先于历史说法，矛盾需要在记忆及回应中说明。

模型可检索全部历史，输入默认只带近期原文与活动记忆。反馈日期与提交时间都保留，避免将补录旧反馈当成今天状态。训练与饮食重新规划时也获得相关个人记忆。

## 压缩

压缩由估算的上下文token预算触发，不由SQLite空间触发。压缩旧记忆并保留证据引用；原始反馈和历史记忆快照不删除。当前限制、未解决问题和关键偏好属于保护项，压缩不能悄悄丢弃。

压缩生成候选、校验引用与保护项、检查原始版本是否变化后保存新版本。失败保留旧版，明确告知记忆未更新；不得假称已经记住。模型无法看到全部记忆时明确暴露加载范围，允许检索。

## 一致性与失败

记忆和分析使用原文修订及输入快照作并发检查；重复处理同一输入应幂等。模型失败保留原文并可重试，旧记忆和计划保持。计划调整失败保留模型回应及记忆，明确调整失败原因。旧反馈界面和导入导出保留兼容。

## 验证

测试模型选择不调整时不调用规划器；缺少字段仍能回应并记录记忆；历史检索与追问有原文；压缩保留引用/关键限制；更正与旧版本并发失效；失败原文保留；当天与长期权限边界；备份迁移；页面直接展示回应而非强制字段表单。
