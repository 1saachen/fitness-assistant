# 长期补剂规划设计

用户于2026-10-22确认：接入项目现有补剂知识库，在长期计划中增加独立的补剂建议模块。

SupplementPlannerAgent 复用 AgentRuntime，与训练、饮食规划顺序协调。输入为当前档案、饮食候选、训练循环、补充条件、近期原文及个人记忆。将全部已批准补剂知识卡及证据标签提供给模型，避免关键词漏检；待审核和被拒绝卡不进入上下文。无批准卡时仍可说明信息缺口，但不能生成没有来源的产品建议。

输出保存 summary、budget_note、items、questions。每项包含名称、优先级（可以考虑、条件满足再考虑、目前没必要、需要核实）、已有产品名称（新增项为空）、理由、适用条件、饮食替代、注意事项和来源 ID。已有产品逐项覆盖；缺少对应来源时只能标为需要核实。按用户于2026-10-22的后续要求，具体判断由模型完成，本地仅校验结构、来源资格、已有产品覆盖和条件建议的条件字段；取消剂量、医学措辞、健康/用药状态及记忆限制的内容拦截。模型原文通过数据完整性检查后直接保存和展示。没有适合的新增项是有效结果。

来源完整快照由程序从已审核输入复制，保存实际被引用的卡片、创作者、视频、原文解释、证据等级和安全边界。页面逐项展示来源和证据局限，来源 URL 只允许 HTTP(S)。批准不代表科学共识。提示词继续要求审慎处理健康限制和用药信息，不生成个体剂量、品牌购买清单或缺乏症诊断；这些由模型遵循提示，本地不再按措辞拒绝输出。

新模块仅在在线生成长期计划时运行；失败或需要输入时不保存部分计划，沿用现有错误及补充条件流程。补剂结果和调用轨迹随新长期草案保存，确认后启用。已有长期记录没有该字段时正常显示，历史测试内部 demo 路径不生成模拟补剂推荐。当天计划本次不增加服用排程。
